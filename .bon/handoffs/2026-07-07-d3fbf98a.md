**The `/status` recentEvents buffer is a zero-instrumentation client-behaviour verifier.**
When you need to know what the phone actually did — did the user tap, did a poll fire, did
a page load — the circular event buffer answers from the server side: tonight it proved the
launcher's new 20-second roster poll was beating from Sameer's device (two `/sessions`
fetches 20s apart) and reconstructed his whole test sequence (POST /session → page load →
launcher → poll), without touching the phone or adding a line of logging. For a mobile UI
you cannot see, check `/status` before asking the user what happened — it is the rough
sensor for interaction, the way self-screenshots are for rendering. Pairs with the roster
contract: the roster is now three-kind (rc/vertex/local) and anything adding a kind must
touch the classifier (bridge-logic), the launch.html render, and CLAUDE.md's `/sessions`

## For Claudes to come

**ONE live driver per session JSONL is Guéridon's load-bearing invariant, and the whole
session-joining story is downstream of it.** Two `claude` processes resuming the same session-id
both append to one JSONL → interleave and corrupt. That single fact is *why*: a foreign
`vertex-terminal` session is read-only (no pty handle, and resuming collides with the live
terminal); the launcher hides repos with a live session (gdn-wuvujo) so a 2nd launch can't resume
a JSONL the first is writing; and the parked baton-pass (gdn-kidowe) is a hand-off (SIGTERM the
old → then resume), never a simultaneous mirror. When you add any attach/join/resume affordance,
ask first: *could this put a second live process on a JSONL another process is writing?* If yes,
it must hand off, not share. The corollary that explains the "stale view" bug: Guéridon renders a
session it doesn't own as a **one-time snapshot** (`replayFromJSONL` fires once at attach, no
watcher) — live-tailing a foreign session would need a watcher+SSE path, deliberately NOT built
(streaming lane is maintenance-mode). And a `claudev`/`claudefv` session hides its Vertex flag in
the **cmdline `--settings`**, not environ — any "is this Vertex?" check must read both.

## For Claudes to come

**SIGTERM is a faithful `/exit` for a `claude` process.** It triggers claude's `process.on("SIGTERM")`
GracefulShutdown: SessionEnd hooks fire, the session JSONL flushes, the session stays resumable
(`claude --resume <id>`). Verified to the hook-log (`~/.claude/logs/notes-capture.log` archived the
SIGTERM'd session). So the reliable way to *programmatically* end a claude session is **SIGTERM** — not
SIGHUP (claude survives it; it's what `node-pty`'s `pty.kill()` sends by default, so pass the signal
explicitly), and not scraping the TUI to type `/exit` (view-state fragile — gets swallowed by an
in-progress turn or an AskUser menu).

**A turn's "done / ready for input" is cleanly readable from the session JSONL as `stop_reason: end_turn`**
(or an AskUserQuestion tool awaiting input) on the latest assistant message — a structured signal, no
view-sniffing. The bridge can locate a session's JSONL from just the folder path (newest `*.jsonl` in
`~/.claude/projects/<encodePath(folder)>/` created after spawn). Caveat: `/open` latency is UNBOUNDED —
a good run is ~1m45s, a context-less repo's `/open` flailed past 220s without ever reaching `end_turn`.

**Auto-`/open` only makes sense where the repo has `.bon`/handoff context** — in an empty repo `/open`
has nothing to orient to and pokes around endlessly (14 tool calls, never finished). Gate it on `.bon`.

**Native-app deep-linking a remote RC session is a dead end (closed 2026-06-29).** Universal Links
(`claude.ai/code/session_*`) are unforceable from JS by design, AND the installed Mac app
(`com.anthropic.claudefordesktop`) carries no `applinks` entitlement (the AASA names a different,
un-installed bundle `…claudenestfordesktop`). The one forceable custom scheme, `claude-cli://open?cwd&repo&q`,
launches a NEW LOCAL session (no session-id input) — it can't attach to a remote session. So the driving
surface is web / Claude-Desktop-via-account-sync; native-attach is gated on Anthropic shipping an entitled
handler. Don't re-investigate without new evidence (e.g. a new app build / AASA change).

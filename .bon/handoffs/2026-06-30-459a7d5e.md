## For Claudes to come

**The launcher↔conversation hash is part of the routing contract, and it's RAW.** The folder
name (`owner/repo`, always a slash) travels launcher → `location.hash` → conversation-page
matcher, compared against `folder.name`. Anything that writes `location.hash` must use the raw
name — do NOT `encodeURIComponent` it (the `%2F` desyncs the compare and bounces every launch
home). This is the second instance of "folderName is a routing contract" in understanding.md;
the durable guard is `matchFolderFromHash` (render-utils.cjs), which tolerates both forms.

**The launcher's inline JS is a test blind spot.** `launch.html` and `index.html` run inline
`<script>` that the suite can't import. The lesson from the raw-hash bug: when a contract lives
in inline JS, extract the pure logic into a `client/*.cjs` module (the established pattern —
window.Gdn + module.exports + createRequire in tests) so it gets unit-tested. A wrong write-layer
reached production precisely because nothing tested that seam.

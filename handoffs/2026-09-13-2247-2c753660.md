### Reflection
The vidame essayeur earned its keep: my first commit blamed a same-millisecond tie broken by readdir order and shipped a path tie-break as "a second belt". The essayeur ran the OLD test against the NEW product code and it still failed 5/20 — so the tie-break fixed a case that never failed. Sameer's falsifier for the card was "we just end up with more complications in future", and the tie-break was exactly that; it is gone. Lesson in the shape of a rule: when you ship a fix with two parts, ask which part the known-bad actually needed — the extra belt is where complication accretes.

The fusijo measurement instrument was a 200 ms poller on `/sessions` stamping AFTER each response, with CC's own `statusUpdatedAt` as the reference clock — so the number is "how long after CC knew did the roster know", not anything derived from the screen. The second bridge needed a scratch `HOME` because `reapOrphans()` at boot SIGTERMs every pid in the shared `~/.config/gueridon/sse-sessions.json` — a dev bridge started with the real HOME would have killed the live bridge's Vertex-lane children. ## For Claudes to come

**CC's session registry is the roster's state source, and a rendered screen never was.** `<configDir>/sessions/<pid>.json` carries `status` from CC's own state machine — `idle` at the prompt, `busy` mid-turn, `waiting` while a permission, AskUserQuestion or plan dialog is up, and at least one more value (`shell`). An inotify watch on the two seat directories delivers a dialog to the bridge in ~250 ms, before a tmux screen poll can even match it, and the return to idle just as fast. Classify permissively — `waiting` and `busy` by name, anything else CC writes as "fine", ABSENT as `unknown` — because batch `-p` sessions (Garni's verifiers, nineteen live rows) write a record with no `status`, and "no status" rendered as idle would call a session fine that nobody has looked at. Phone children (`--print --sdk-url`, also `entrypoint: sdk-cli`) DO carry a status on 2.1.270 — two live records read idle/busy on 2026-09-13 — with `tmux` null; the discriminator is `-p` vs `--sdk-url`, not the entrypoint, and the 12 Sep memory line saying phone sessions lack `status` is superseded. The record dies seconds after the process, which is why the same watcher must also journal (gdn-daluto): one reader, two sinks.

**A permission dialog cannot be provoked in bypass mode, and the estate defaults to bypass.** An `ask` rule is silent under `bypassPermissions`; only `deny` holds there. Any probe that needs a real dialog launches with `--permission-mode default` (the pane then reads `manual mode on`) and an inline `--settings '{"permissions":{"ask":["Bash(touch *)"]}}'`. The wrappers' billing survives a trailing `--settings` because they also set it as an `env` prefix. Measured on both wrappers, 2026-09-13.

**A second Guéridon bridge needs a scratch `HOME`.** Its boot calls `reapOrphans()`, which SIGTERMs every pid recorded in the shared `~/.config/gueridon/sse-sessions.json` — the LIVE bridge's children. `HOME=/tmp/<scratch>` with `.claude/sessions` and `.claude-commis/sessions` symlinked to the real directories gives a dev bridge the real registry and none of the shared state; kill it by the pid `ss -ltnp` names, and remove the scratch home explicitly.

**A two-part fix is a question, not a belt-and-braces.** When a fix ships as "the real change plus a second belt", run the known-bad against each part alone before writing the mechanism into the commit message. gdn-vidame's tie-break passed every test, fixed nothing that had failed, and carried a wrong causal story into the record for forty minutes; the essayeur's old-test-against-new-product arm is the cheap discriminator, and the falsifier "more complications in future" is what such belts violate.

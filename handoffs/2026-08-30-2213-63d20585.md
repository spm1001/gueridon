## For Claudes to come

**When two instruments each have a structural blind spot, design for their union — don't pick the less-bad one.** The live-session question had no single honest source: the `/proc` scan sees every wallet but knows almost no session uuids; each wallet's `claude agents --json` registry knows uuids but is per-config-dir blind (sameer@'s cannot see family@'s, measured both directions). The switchboard's liveness layer is the union of both plus Guéridon's own registries, and each component covers a hole another can't. The generalisation: when you catch yourself ranking imperfect instruments, check whether the right design consumes all of them.

**Claude Code /proc identity mechanics, all measured on 2.1.250/251:** `readlink /proc/<pid>/exe` → `~/.local/share/claude/versions/<v>` is the universal is-this-claude discriminator (comm lies: RC-server children run under the versioned binary so their comm is "2.1.251"). An RC child's cmdline carries its `cse_` work id in `--sdk-url` — exact teleport identity, offline. Some infra rewrites its process title so argv[0] becomes one space-joined token ("claude bg-spare") — and a `tr '\0' ' '` eyeball view renders space and NUL identically, which is precisely how that hid. Infra subcommands now include `rc` (a second server alias) and the daemon's `bg-spare`/`bg-pty-host` pool.

**Transcript size separates machine probes from human conversations.** On this estate every auto-spawned probe session (hublot drives, ardoise cold reads, gate probes) measured ≤75KB while every human session measured ≥140KB — a 100KB floor with human-surface-title exemptions (Cowork sidecar, RC bridge log) cleaned a cluttered session list in one move. Cheap, tunable, and honest about its one measured survivor (a robot session doing real work).

## For Claudes to come

The durable architecture finding is already in `understanding.md` → **Billing lanes — Vertex
vs Teams** (read it there). The one-line essence worth carrying: **a remote-control / relayed
UI binds to a first-party account identity; a session billed through a third party (Vertex/GCP)
has no such identity, so remote-attach is structurally impossible — and it fails SILENTLY (a
plain local session, no URL), not loudly.** Generalises beyond gueridon: any "attach the vendor's
hosted UI to my session" feature is gated on the session carrying the vendor's own identity, and
the absence shows up as quiet degradation, not an error — so always test the negative directly.

## For Claudes to come

**A Claude Code registry record is not proof of a process.** CC writes `<configDir>/sessions/<pid>.json` at session start and deletes it on a clean exit, but an unclean end leaves it behind: in the small hours of 2026-09-14 (01:15 BST, the night of 13–14 September) two phone-child records sat in the registry with pids dead for about two hours, one still saying `busy`. `claude agents --json` filters those out silently rather than deleting them, and the next `claude` start on that seat sweeps them (measured on both seats the same night). So any consumer that means "a driver is alive" must check the pid — and check it is a Claude binary, since pids recycle — rather than trusting the record's presence. Guéridon's roster was safe by construction (it joins on the `/proc` scan's live pids); its `/recent` band and the new ledger both had to be taught. The corollary for a journal keyed on these records: `ended_at` on a swept stale row is the sweep time, not the death; CC's own `updatedAt` (the ledger's `last_seen`) is the better "when did it stop".

**A `session_…` id on a session does not mean its transcript is the uuid5 of that id.** Phone children are minted from the id, so their transcript uuid is uuid5(cse body) — a v5 uuid. But an ordinary terminal `cli` session on a Teams seat acquires a `bridgeSessionId` too, seconds after open, because remote control attaches to it — and its transcript is its own v4 uuid. The uuid5 derivation then names a transcript that does not exist. Where a registry record or a ledger row has been observed, the observed sessionId is the answer and the derivation is a cross-check; `uuidVersionOf(sessionId) === 5` is the test for whether the derivation was ever supposed to hold. One of three teleport-bearing rows in the first live ledger was such a `cli` session; a resume built from the derivation would have resumed nothing.

**A wrapped `grep` on a file it classes as binary prints nothing at all** — not "binary file matches", nothing — and one stray control byte is enough. A Write once put a literal NUL inside a template literal; every later in-harness grep on that file was a silent zero, and a mutation check built on that grep declared a mutant landed when the anchor had never matched. `rg` and `command grep` both announce "binary file matches"; `od -c -j <offset>` shows the byte. Before trusting a null on a file you just wrote, `rg -a` it once. (Filed for the corpus as carte-jalowo.)
